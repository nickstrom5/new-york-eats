## Data rules (the product's promise)
- **Official records first, kept to their own jurisdiction, never blended:**
  - NYC: DOHMH's posted letter grade and its date are shown as official. Never derive a grade from the score (2025–26 rows have C at
    score 0 and B from 7 to 34). Pests = 04K/04L/04M only; 08A ("conditions conducive") is not pest evidence.
  - Counties outside NYC, Suffolk and Erie: NYSDOH's latest inspection date and critical / not-corrected / non-critical counts only. No
    grade exists; quote NYSDOH's disclaimer verbatim plus "Any analyses, interpretations or conclusions here are ours, not NYSDOH's."
    The dataset's notes also say "Researchers agree to: Use the data for statistical reporting and analysis only". Nick's call
    (2026-10-07): the app and site show these as facts per place (date + counts + disclaimer), never ranked or graded; only the private
    leaderboard keeps its "State inspections" board.
  - Suffolk: "violations cited in 2025" (yearly layer). Erie: HealthSpace is search-only and blocks us; only Buffalo's license list.
- Only trade names (DBA) are ever used. Legal names, operators and owners are never downloaded (`pipeline/fetch_official.py`).
- Records-through dates come from each feed's own refresh date minus 7 days (`official.records_through`), never hard-coded.
- Guides list only **hand-checked** places (`data/research/app/*.json`, each with a 2025–26 source; see `data/research/README.md`).
  Honors (MICHELIN 2025 selection, James Beard 2023–26, America's Classics) are facts, never star ratings. Honorees with no 2025–26
  evidence of being open only annotate an existing listing.
- Never fetch a host whose robots.txt disallows ClaudeBot / Claude-User / anthropic-ai (guide.michelin.com does). Never bypass bot
  protection; never scrape search-only inspection portals (ABCEats, HealthSpace, Nassau's lookup).
- `pipeline/check_sources.py` checks every host the research cites (robots.txt for ClaudeBot, Claude-User, anthropic-ai, and bot
  checks; `data/research/source_hosts.json`, 7-day cache) and must report 0 unusable before a release; `check_sources.py <url>` checks
  a new source before anyone reads it. Stage 2 drops any source on a blocked host on its own, and skips research records flagged
  `"recheck": true`. The 2026-10-08 audit found 11 blocked hosts the first research wave had used (visitbuffalo.com is behind a
  Cloudflare check; romesentinel.com, theinfatuation.com, Spectrum News and others disallow ClaudeBot): their URLs were removed and
  64 guide records re-sourced or moved to leads (`data/research/removed_sources.json`).

## Rebuild
```bash
.venv/bin/python pipeline/fetch_official.py      # DOHMH, NYSDOH, Suffolk, Buffalo, SLA, Ag & Markets -> data/raw/official
.venv/bin/python pipeline/fetch_overture.py      # Overture places (2026-09-23.1) -> data/ny/overture_ny.parquet
.venv/bin/python pipeline/fetch_geo.py           # Census counties + county subdivisions, NYC NTAs -> data/ny
cd pipeline
../.venv/bin/python official.py                  # one table of official records -> data/ny/official.pkl
../.venv/bin/python listings.py                  # clean + place listings, Google 2021 match -> data/ny/stage1.pkl
../.venv/bin/python calibrate.py                 # match rates + per-county coverage -> data/ny/calibration.json
../.venv/bin/python newyork.py                   # web leaderboard -> site/ny-*.json
../.venv/bin/python check_sources.py              # every research source's host vs robots.txt and bot checks (must be 0 unusable)
NY_APP=1 ../.venv/bin/python newyork.py          # app data -> data/app/index.json + places-<region>.json (NYC: one file per borough)
../.venv/bin/python check_websites.py            # every candidate link, politely (hours); then rerun the NY_APP=1 export
cd .. && .venv/bin/python scripts/make-leaderboard.py   # site/index.html (then republish the artifact with the 22 site/ny*.json)
rm NewYorkEats/Resources/Data/places-*.json && cp data/app/index.json data/app/places-*.json NewYorkEats/Resources/Data/   # bundled data
.venv/bin/python scripts/make-site.py && .venv/bin/python scripts/qa-site.py   # website + web app in docs/, then headless QA
.venv/bin/python scripts/listing-copy.py         # App Store listing + App Review reply, numbers from the data, limits asserted
```
Brand: `swift scripts/make-brand.swift` (icon, favicons, og image), `.venv/bin/python scripts/make-outline.py` (the state outline the
app header and site use). Research geocoding: `pipeline/geocode_research.py` (Census geocoder) for addresses stage 2 couldn't place.

## Build the app
- The Xcode project is generated: `xcodegen generate`. Never commit `NewYorkEats.xcodeproj`.
- Compile check without a simulator: `DEVELOPER_DIR="/Applications/Xcode 1.app/Contents/Developer" xcodebuild build-for-testing -project
  NewYorkEats.xcodeproj -scheme NewYorkEats -destination 'generic/platform=iOS Simulator' -derivedDataPath ./DerivedData CODE_SIGNING_ALLOWED=NO`
- Light mode only (`UIUserInterfaceStyle: Light`). `-screenshot <home|slices|bagels|wings|detail|map|icons|saved|about>` is DEBUG-only
  (Washington Square Park as "you"). `scripts/capture-screenshots.sh "<sim>"` (PREFIX=ipad- for the iPad set) writes screenshots/.
- The data is ~15 MB of JSON in 14 files (nine regions + New York City's five boroughs), decoded in parallel off the main thread, with
  the A-to-Z order sorted there too; lists are memoized (AppModel), because New York has 6x Connecticut's places. `Search.normalize`
  runs 190,000 times at launch, so it's a single pass over the characters (4x the old regex version, identical output).
The venv is an APFS clone of ct-eats' (`cp -c -R`). The UCSD 2021 listing file is `data/meta-New_York.json.gz` (web only).
